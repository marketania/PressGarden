# PressGarden 0.1.3

Clean-now prompts after a cleanup preview and a manual cleanup command for old
PressGarden backups.

## Everyday use

- In a terminal, `cleanup` now asks `Clean now? [y/N]` after the preview, once
  for each selected category that has candidates: database transients and
  revisions, disposable files, rotated logs and development caches. The default
  is No. Yes runs that category's normal execute path, with its private backup,
  exact candidate list, per-site confirmation and verification. Piped or
  unattended runs, `cleanup status`, and previews with incomplete or review
  items never prompt.
- `backups prune --older-than=DAYS [--apply]` removes old PressGarden backups.
  It previews by default. Only completed file-cleanup backups and
  checksum-verified database dumps are eligible. The newest backup per site and
  category is kept. Apply must match the previewed set exactly and is logged.
  Reported bytes are logical, not net disk space reclaimed.

## Update

From an installed PressGarden directory, finish other operations and run:

```bash
./pressgarden update
./pressgarden version
./pressgarden config-new
```

Use `PRESSGARDEN_REF=v0.1.3 ./pressgarden update` to select this release
explicitly. Private configuration and state are preserved. There are no data
migrations or new sibling dependencies. Source publication does not run
maintenance against any website.
