# PressGarden 0.1.2

Unified routine cleanup, clearer terminal results, and a newcomer guide with
selected-source installation and practical first-run examples.

## Everyday use

- `cleanup SITE` previews disposable metadata, old rotated logs, generated
  development caches, and expired database transients together. Narrow that
  preview with any combination of `-db`, `-files`, `-logs`, and `-development`.
  Revisions remain an explicit selection. `--execute` requests the guarded
  action; backup, snapshot, target and confirmation checks still apply.
- Fleet output uses a compact colored table, measured totals, and clear
  ready/review/incomplete states. `--verbose` adds bounded details. Color controls
  and plain redirected output are supported.
- Grouped help, topic help, status shortcuts and named targets make common
  operations easier to find. Existing command aliases remain supported.
- The README explains requirements, selected releases, configuration, nested
  sites, result meanings, troubleshooting and recovery.

## Correctness and preservation

- Refuse unusable, syntactically invalid or failed saved configuration before
  dispatch. Preserve exact exported scope and multiline exclusions; refuse
  readonly saved values that prevent an explicit override.
- Report empty doctor scopes, invalid config roots, unavailable providers and
  invalid status responses honestly. Keep unselected revision measurements
  distinct from unavailable database measurements, and sanitize provider output.
- Preserve security evidence, project settings and recovery directories during
  cleanup. Validate complete eligible content, confirm actual candidates, reject
  changed snapshots and retain private backup/removal manifests.
- Bind database mutations to the selected table plan and database identity, and
  retain multisite/cache scope guards. Add isolated WordPress/MySQL recovery
  coverage for scoped and whole-database backups and damaged-backup refusal.

## Update

From an installed PressGarden directory, finish other operations and run:

```bash
./pressgarden update
./pressgarden version
./pressgarden config-new
```

The ordinary updater follows moving `main`; use
`PRESSGARDEN_REF=v0.1.2 ./pressgarden update` to select this release explicitly.
Private configuration and state are preserved. `config-new` previews missing
options without changing the saved file. Git checkouts are maintained through
Git; use a separate portable installation for the program updater.

There are no data migrations or new sibling dependencies. Source publication
does not run maintenance against a website. Fixture recovery coverage does not
verify an individual production backup. See the
[README](https://github.com/marketania/PressGarden/blob/v0.1.2/README.md) and
[update recovery guide](https://github.com/marketania/PressGarden/blob/v0.1.2/docs/UPDATING.md)
for operation and recovery details.
